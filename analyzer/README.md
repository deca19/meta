# ZETA 주제 기회 분석기

작품 카탈로그를 넣으면 **"다음에 어떤 주제를 만들면 좋은가"** 를 점수로 계산하는 엔진.

```
analyzer/
├─ zeta-analyzer.js    엔진 (의존성 없음, Node/브라우저 공용)
├─ sample-works.js     합성 샘플 데이터 생성기
├─ analyzer.test.js    검증 178항목
├─ collect.html        작품 수집기
└─ index.html          분석 대시보드
```

```bash
node analyzer/analyzer.test.js     # 검증
open analyzer/collect.html         # 수집 → "분석기로 보내기"
open analyzer/index.html           # 분석 대시보드
```

---

## 데이터에 대한 전제

**이 저장소에는 ZETA의 실제 데이터가 없다.** 샘플은 엔진 동작 확인용으로 만든 합성 시장이며,
거기서 나온 "오피스 × 집착이 유망하다" 같은 결론은 **가짜 데이터에 대한 사실**일 뿐 ZETA에 대한
주장이 아니다. 실제 분석에는 직접 수집한 데이터를 넣어야 한다.

### 수집 방식이 결론을 결정한다

지표를 아무리 정교하게 다듬어도 표본이 편향되면 결론도 편향된다. 그리고 이 편향은
표본을 늘려도 줄지 않는다.

| 수집 위치 | 편향 | 권장 `sampling` |
|---|---|---|
| **최신순 탭** | **없음** — 성과와 무관하게 노출됨 | `census` |
| 인기순 탭 | 생존편향 — 실패작이 표본에 없음 | `ranked` |
| 추천 피드 | 노출 편향 — 대화수가 알고리즘 노출을 반영 | `ranked` |
| 검색 결과 | 키워드 편향 — 해당 태그 공급이 과대 표시 | 주의 |

**최신순 100건이 인기순 1000건보다 낫다.** 인기순만 모으면 "이 조합은 잘 된다"는 결론이
"잘 된 것만 봤다"의 동어반복이 된다. `ranked` 보정은 gap을 중립 쪽으로 절반 당길 뿐,
없는 실패작을 만들어내지는 못한다.

수집기는 각 작품에 `source`를 기록하고, 분석기는 그 구성을 검사해 `sampling` 설정이
데이터와 맞지 않으면 경고한다. 최신순 표본이 0건이면 별도로 알린다.

### 수집기 (`collect.html`)

앱 화면을 보면서 기록하는 도구. 손이 키보드를 떠나지 않게 설계했다.

- **붙여넣기 파싱** — 카드 텍스트를 붙여넣으면 제목·해시태그·숫자·날짜를 분리한다.
- **한국식 표기 그대로** — `12.3만` → 123000, `3일 전` → 날짜. 손으로 환산하면 반드시 틀린다.
- **태그 자동완성** — 사전 키워드 + 이전에 쓴 태그. `↓` `↑` `Enter`.
- **축 커버리지 실시간 표시** — 축 1개만 채워지면 그 작품은 조합 분석에서 빠진다고 즉시 알린다.
  수집이 끝난 뒤에 발견하면 되돌릴 수 없다.
- **표본 충분도** — 60건 미만은 조합 추천 불가, 150건이면 충분. 진행 막대로 표시.
- **자동 저장** — 새로고침해도 유지. 80건 날리는 사고가 나면 안 된다.
- **미등록 태그 집계** — 사전 보강 지점을 수집 중에 알려준다.

입력 스키마:

| 필드 | 설명 | 필수 |
|---|---|---|
| `id` | 작품 식별자 | 권장 |
| `title` | 제목 (태그가 부실할 때 보조 분류 신호) | — |
| `tags` | 태그 배열. CSV에서는 `\|` 구분 | **필수** |
| `createdAt` | 생성일 (ISO). 없으면 180일 전으로 가정 | 권장 |
| `chats` | 누적 대화수 = 수요 대리변수 | **필수** |
| `likes` | 좋아요 수 → 만족도 계산 | 권장 |
| `creatorFollowers` | 제작자 팔로워 → 진입장벽 계산 | 권장 |
| `source` | `new` / `popular` / `recommended` / `search` — 표본 편향 검사 | 권장 |
| `rank` | 목록에서의 순위 | — |

숫자 칸은 `12.3만`, `8,420`, `1.5K` 같은 표기를 그대로 넣어도 된다.

## 알고리즘

### 1. 분류 — 태그를 5개 축으로

장르 / 관계 / 정서 / 배경 / 캐릭터. `TAXONOMY` 사전이 태그를 축 값에 매핑한다.

- **태그는 완전 일치, 제목만 부분 일치.** 태그에 부분 일치를 쓰면 `집착남`(캐릭터:얀데레)이
  `집착`(정서) 키워드에도 걸려 두 축이 항상 함께 켜지고, 결과적으로 `집착 × 얀데레` 같은
  동어반복이 추천 1위로 올라온다.
- **하나의 키워드는 하나의 축에만.** `validateTaxonomy()` 가 위반을 검출한다.
- 매핑 안 된 태그는 `unmappedTags` 로 보고되어 사전을 보강할 수 있다.

### 2. 수요 측정 — 윈저화한 일평균 대화수

```
velocity = chats / 경과일수
demand   = min(velocity, p95)
```

- 누적 대화수는 나이의 함수라 오래된 작품이 구조적으로 이긴다 → 속도를 쓴다.
- 로그를 씌우면 측정하려던 인기 격차 자체가 뭉개진다. 초기 버전이 그랬고 모든 `gap`이
  0.95~1.11에 몰려 아무것도 구분하지 못했다.
- 대신 상위 5%를 절단해 초대형 히트작 하나가 셀을 좌우하는 문제를 막는다.
  덕분에 `gap 2.0` = "공급 대비 실수요 2배" 로 그대로 읽힌다.

### 3. 셀 집계

다중 라벨 작품은 **1/n 로 분할 귀속**한다. 태그 3개짜리 작품을 3번 세면 공급 총량이 부풀어
공급 비중이 왜곡된다.

셀마다 계산하는 지표:

| 지표 | 정의 | 의미 |
|---|---|---|
| `gap` | 수요 비중 / 공급 비중 | >1 이면 수요가 공급을 앞섬 |
| `momentum` | 셀 최근작 성과 / 전체 최근작 성과 | 신규 진입자가 잘 되는가 |
| `trend` | 코호트별 수요 점유율의 회귀 기울기 | 시간에 따라 오르는가 내리는가 |
| `openness` | 1 − HHI | 상위 독식이 아닌 정도 |
| `newcomer` | 저팔로워 제작자의 평균 이상 달성률 | 진입장벽 |
| `quality` | 대화당 좋아요 | 만족도 |
| `staleness` | 작품 나이 중앙값 | 리프레시 여지 |
| `fit` | 내 작품의 축별 상대 성과 | 시장 기회 ≠ 내 강점 |
| `supplyRush` | 최근 공급 비중 / 과거 공급 비중 | 경쟁 유입 (리스크 판정 전용) |

> `momentum`은 성장률이 아니라 **신작 성과 지수**다. 셀 내부에서 최근작과 과거작을 비교하면
> `velocity = chats/나이` 가 나이에 따라 체계적으로 감소하는 효과와 뒤섞인다.
> 최근작끼리 비교하면 그 편향이 양쪽에 동일하게 걸려 상쇄된다.
>
> 방향은 `trend`가 따로 잰다. 코호트(기본 90일 단위 4칸) **안에서** 점유율을 계산하므로
> 나이에 따른 velocity 감소가 분자·분모에 동일하게 걸려 상쇄된다.

### 4. 소표본 보정 — 이 엔진에서 가장 중요한 부분

```
gap_adj = (n · gap + k · 1) / (n + k)     # k = priorStrength, 기본 8
```

표본이 적을수록 중립값 1로 당긴다. **이게 없으면 작품 2개짜리 희귀 조합이 항상 1위가 된다.**
작품 1개짜리 셀의 `gap 20`은 3 이하로 눌린다.

### 4-b. 신뢰구간 — 점수를 정밀한 값으로 착각하지 않기

축소만으로는 부족하다. `78.1` 과 `72.4` 가 나란히 있으면 전자가 더 낫다고 읽게 되지만,
표본이 6개와 20개면 애초에 비교 가능한 숫자가 아니다.

셀 구성원을 복원추출로 재표본(기본 200회)해 `gap` 의 분포를 만든다.

```
작품 5개  → gap 1.81, CI [1.20, 2.09]   ← 1을 벗어남, 유의미
작품 9개  → gap 1.39, CI [1.00, 1.88]   ← 1을 걸침, 판단 유보
작품 11개 → gap 1.16, CI [0.92, 1.43]   ← 1을 걸침, 판단 유보
```

샘플 데이터에서 **검증형 추천 8건 중 신뢰구간이 1을 벗어나는 것은 1건뿐이다.** 나머지 7건은
"수요가 공급을 앞선다"고 단정할 근거가 없다. 이 사실은 경고로 항상 함께 출력된다.

`conservative: true` 로 두면 점추정 대신 **신뢰구간 하한**으로 순위를 매긴다.
"가장 좋아 보이는 셀"이 아니라 "나쁠 리 없는 셀"을 고르는 방식이고, 표본이 적어
구간이 넓은 셀은 자동으로 밀려난다.

시드 고정(`seed`)이라 부트스트랩 결과도 재현된다. `bootstrapSamples: 0` 으로 끌 수 있다.

### 5. 정규화와 합산

각 지표를 **백분위**로 변환(롱테일에서 z-score보다 강건) 후 가중합 → 0~100.

정규화는 **비교 대상 전체를 한 풀에 모아** 한 번만 한다. 축 쌍별로 따로 정규화하면 그룹마다
1위가 백분위 1.0을 받아 병합 랭킹이 무의미해지고, 서로 다른 축의 점수를 곱하는 whitespace
계산도 성립하지 않는다.

기본 가중치: `gap .30 / momentum .22 / openness .16 / newcomer .12 / quality .10 / staleness .10`

### 6. 조합 분석

2축뿐 아니라 **3축 조합**(장르 × 관계 × 정서)까지 본다. 실제 "주제"는 보통 세 축이 만나는
지점이고, `오피스 × 상사·부하 × 집착` 은 `오피스 × 집착` 보다 훨씬 구체적인 지시다.
2축과 3축은 **같은 풀에서 정규화**한다 — 따로 하면 각 차수의 1위가 나란히 100점을 받는다.

- **검증형**: 표본이 `minSupport` 이상인 조합. 실제 성과로 뒷받침된다.
- **미개척(whitespace)**: `lift = 관측/기대 < 0.75` 이고 각 축은 매력적인 조합.
  **표본이 없으므로 가설이다.** 수요가 없어서 비어 있을 가능성이 항상 함께 있다.
- **정보량 없는 조합 제외**: 두 축 값의 작품 집합 자카드 중복도가 0.65 이상이면 제외.
  `집착 × 얀데레`(개념적 동의어)와 `학원 × 짝사랑`(항상 동시 출현) 둘 다 걸린다.
  이 지표는 둘을 구분하지 못하지만 구분할 필요도 없다 — 조합 추천 관점에서 양쪽 다
  "단일 축 대비 추가 정보가 없는" 조합이고, 해당 축은 단일 축 랭킹에 이미 나와 있다.

### 6-b. 다양성 선별 — 8개의 선택지 vs 1개의 선택지

점수 상위 8개를 그대로 뽑으면 이렇게 나온다:

```
1. 오피스 × 상사·부하 × 집착   5. 현대 × 미스터리
2. 오피스 × 집착              6. SF·근미래 × 애절
3. 일상·힐링 × 치유            7. 오피스 × 상사·부하
4. 상사·부하 × 얀데레          8. 애절 × 무심
```

1·2·4·7번은 사실상 같은 제안이다. 선택지가 8개인 것처럼 보이지만 실제로는 훨씬 적다.
매 단계에서 `점수 − λ·(이미 뽑은 것과의 최대 유사도)` 가 최대인 항목을 고른다(MMR).
유사도는 공유 축 값 비율(0.6)과 작품 집합 자카드(0.4)의 혼합. `diversity: 0` 이면 순수 점수순.

또 하나: 추천 풀에서 **`gap < 1` 인 셀은 제외한다.** 다양성 선별은 후보가 떨어지면 목록을
채우려 하는데, 공급이 수요를 앞선 구간을 "이걸 만드세요" 라고 내놓는 건 자기모순이다.

### 6-c. 제작자 적합도 (선택)

`myWorks` 에 내 작품을 넣으면 축 값별로 내 성과 ÷ 시장 중앙값을 계산해 점수에 반영한다.
**시장에 기회가 있는 주제와 내가 잘 만드는 주제는 다른 질문이다.** 내 작품 표본은 대개
10개 미만이라 축소 강도를 세게(k=3) 준다 — 1개짜리 기록은 6개짜리보다 훨씬 약하게 반영된다.
`myWorks` 가 없으면 모든 셀이 1.0을 받아 순위에 영향이 없다.

### 7. 레드오션

절대 임계치가 아니라 상대 기준을 쓴다. 임계치는 데이터 스케일이 바뀌면 아무것도 못 잡거나
전부 잡는다(실제로 초기 버전은 0건이었다). **공급 비중 중앙값 이상 + 기회점수 하위 25%** 가
정의상 레드오션이다.

## 이 알고리즘이 답하지 못하는 것

1. **생존편향.** 인기순 상위만 수집하면 실패작이 보이지 않아 모든 `gap`이 부풀려진다.
   `sampling: 'ranked'` 로 절반 보정하고 경고를 띄우지만, 근본 해법은 전수 수집이다.
2. **노출 편향.** `chats`는 순수 수요가 아니라 *추천 알고리즘이 노출한 결과*다. 플랫폼이 밀어준
   작품이 인기 있어 보인다. 이 데이터만으로는 분리할 수 없다.
3. **인과가 아니다.** "오피스물이 잘 된다"가 "당신의 오피스물이 잘 된다"를 뜻하지 않는다.
   실행 품질이 주제 선택보다 분산이 크다.
4. **비어 있는 칸에는 대개 이유가 있다.** whitespace는 가설 생성기이지 검증기가 아니다.
5. **신뢰구간은 표본 오차만 잡는다.** 위 1~2번 같은 계통 편향은 표본을 아무리 늘려도
   줄지 않는다. CI가 좁다고 해서 편향이 없다는 뜻이 아니다.

## 튜닝

```js
ZetaAnalyzer.analyze(works, {
  sampling: 'census',          // 'ranked' → 생존편향 보정 + 경고
  minSupport: 5,               // 검증형 판정 최소 표본
  priorStrength: 8,            // 소표본 축소 강도 (↑ 보수적)
  redundancyThreshold: 0.65,   // 중복 조합 제외 기준

  bootstrapSamples: 200,       // 신뢰구간 재표본 횟수 (0 = 끄기)
  conservative: false,         // true → CI 하한으로 순위
  diversity: 0.45,             // MMR λ (0 = 점수순 그대로)
  cohortDays: 90,              // 추세 코호트 한 칸의 기간
  cohortCount: 4,
  tripleAxes: [['genre','relation','tone']],
  myWorks: null,               // 내 작품 → 적합도 반영

  weights: { gap:.28, momentum:.15, trend:.12, openness:.13,
```
